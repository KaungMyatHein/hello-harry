01 · Situation
The pain

Tokens were drifting every sprint.

At Raytail, design tokens were drifting across 6 platforms — POS, Web, Mobile, and three internal surfaces. Designers exported tokens manually, naming conventions diverged across teams, and the design system was leaking integrity every sprint.

02 · Task
The deliverable

Automate the export step.

Build a Figma plugin that automates token export across all 6 platforms, eliminating the manual export step and the naming drift it caused.

03 · Action
What I did

Built it in the codebase, not in Figma comments.

  • Built the Figma plugin in TypeScript using the Figma Plugin API — handling token traversal, naming normalization, and multi-platform serialization.
  • Integrated with Style Dictionary so a single Figma source compiled to CSS variables, iOS, Android, and JSON token files.
  • Shipped as developer-friendly tooling that plugged into existing build pipelines via GitHub — not as a designer-only utility.
  • Wrote and debugged in Cursor and VSCode, iterating on naming conventions directly with engineers rather than over Figma comments.
  • Ran 3 follow-up enablement sessions to migrate 4 teams off the manual flow — the hardest part was change-management, not the code.

const collections = figma.variables
  .getLocalVariableCollections();

const tokens = collections.flatMap(c =>
  c.variableIds.map(resolveToken)
);

return tokens.map(toStyleDict);

05 · Reflection
What I'd do differently

The technical artifact is half the job.

I would have built the migration guide alongside v1 instead of after launch — teams adopted faster once I had a 1-page "how to move off the old flow" doc, and I should have shipped that with the plugin. Lesson — in design-engineering work, the technical artifact is half the job; the adoption tooling is the other half.
