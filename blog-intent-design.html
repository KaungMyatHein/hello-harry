Intent Design — Software That Listens to You

Stop making the user learn the software. Make the software learn the user.

Author Harry Hein Topic Intent Design Read 5 min

01What is Intent Design?

You type what you want. The app does it.

No menus. No clicking through tabs. One text box.

  • Old way: "Where is the button to mark this order paid?"
  • New way: "Mark order #1042 paid." → done.
flowchart LR
    A[Type a sentence] --> B[Intent Classifier]
    B --> C[Action happens right there]

Empty palette — one text box, infinite intents.

02Why Intent Design?

Menus make new users do homework:

  1. Where is the feature?
  2. What is it called?
  3. Which clicks open it?

Intent Design skips all three. The user speaks. The system meets them.

"We make the system understand the user — not the other way around."

03What You Need to Know

Four pieces.

3.1 Classifier first, AI second

Regex matches common queries in 50ms. AI handles only the weird stuff.

flowchart LR
    Q[query] --> R[regex ~50ms]
    R -->|match| OK[card]
    R -->|no match| AI[AI ~2s]
    AI --> OK

3.2 Build cards, not paragraphs

Every answer is a small interactive card. The user acts right there.

Real listing page — cards over paragraphs.

3.3 Card and page share one URL

Same filters in both places. They never disagree.

flowchart LR
    P["Palette card"] --> U["?customer=Khin&status=PENDING"]
    U --> Pg["/orders page"]

3.4 Chain the next step

After each result, show 2–3 follow-up chips. One palette open, many actions.

Chain flow — each action suggests the next.

Five wins

  1. No learning curve.
  2. Any language works.
  3. Action happens in place.
  4. Fast for experts, easy for beginners.
  5. Accessible by default (type = speak).
Traditional: "Learn me first."
Intent: "Tell me, I'll do it."
