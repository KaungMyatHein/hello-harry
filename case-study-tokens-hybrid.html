01 — The problem

Every release. 2–3 hours. Naming.

The design system promised speed. Manual token exports broke that promise every release.

Designers exported tokens from Figma. Developers manually translated to platform formats. CSS needs camelCase. Swift needs PascalCase. Kotlin needs snake_case. Every release, developers spent 2–3 hours fixing naming mismatches.

Every sync failure eroded trust between design and engineering. The design system promised speed — manual token exports broke that promise every two weeks.

What if we could export once and use everywhere? And catch errors before they ever hit code?
02 — Discovery

Naming was the #1 frustration.

Interviewed 4 designers and 6 developers across POS, web, and mobile platform teams.

10/10
Confirmed naming as the bottleneck
Not missing tokens. Not wrong values. Wrong names. Every platform's convention silently broke the handoff.
3 teams
Each with its own convention
POS uses camelCase. Web uses kebab-case. Mobile uses snake_case in Kotlin and PascalCase in Swift. No single source could win.

Key finding: the gap isn't between Figma and code. It's between Figma variables and platform-specific naming conventions. The solution had to live at the export layer — not in Figma's source, and not in the dev branch.

Store the truth once. Translate on export.
03 — Four core jobs

What the plugin had to do.

Job 01Filter by token type

Colors, spacing, typography, shadows don't all export the same way. Give designers control over what ships per release.

Job 02Support light & dark modes

One variable, multiple theme values. Export them in a single pass — no separate runs per theme.

Job 03Smart naming conventions

Apply camelCase, PascalCase, or snake_case on export. Match platform norms automatically — never edit the Figma source.

Job 04Sync to Notion

Single source of truth. Designers and developers see the same data in real-time, with version history attached.

04 — Plugin architecture

Four stages. Zero manual translation.

  1. Discovery. Read all Figma variables from selected collections automatically. No manual selection. No copy-paste.
  2. Config. Choose naming convention. Select which modes to include. Pick which platforms to export for in this run.
  3. Preview. See generated code in real-time before export. Catch errors at zero cost — they never reach the dev branch.
  4. Export. CSS, JS/TS, Flutter, Kotlin, Swift, JSON — all from one plugin, one run, one release.
The preview stage turned out to be the hero. Every tester said it caught errors they would have missed.
05 — Usability testing

Two findings that changed the build.

Tested with 3 designers and 2 developers before launch.

Finding 01

Collection selector needed search.

With 40+ collections in the design system, scroll-and-find didn't scale. Added fuzzy search before launch so designers stopped losing 30 seconds at the start of every export.

Finding 02

Preview was the most praised feature.

Every tester said the preview panel caught errors they would have missed. Real-time validation became the trust contract — developers stopped second-guessing imports.

Developers also requested a CLI export — added to the v2 roadmap to support CI/CD pipelines without opening Figma.

07 — Lessons

Five technical lessons.

Lesson 01

Preserve original casing.

Store token names as-is in Figma. Apply conventions only at export. Never overwrite the source — reversibility is the trust contract.

Lesson 02

Test multi-segment names.

"color-primary-hover-dark" exposes casing logic bugs. Test edge cases early — before the design system has 400 tokens to debug.

Lesson 03

Preview catches errors.

Real-time validation eliminates most export bugs before they ship. The preview pane saved more time than the export itself.

Lesson 04

Proxy simplifies CORS.

Local server handles Notion API auth. Eliminates cross-origin headaches and keeps the plugin sandbox clean.

Lesson 05

Smart defaults win adoption.

Default camelCase for JS, snake_case for Python. Less thinking = more adoption. Adoption is what makes a design system stick.
