01 — The Problem

The breaking point.

The brand green changed. A simple hex value update. The team spent two days manually updating components across every platform file. QA still found 14 screens they missed.

Three products shared one Figma file: POS for cashiers, Web dashboard for managers, Mobile for staff. Three radically different interaction models — touch targets, information density, gesture patterns — all crammed into a single library.

The shared file was supposed to keep things consistent. Instead, it became the single point of failure. Every change rippled unpredictably. Every new designer asked the same question on day one.

I don't know which file is right.
New designer · day 3 of onboarding
That file was the problem. But what would the solution look like?

03 — Strategy

Old vs. new mental model.

A shared core that defines what's universal — then platform libraries that extend without redefining the foundation. Changes flow down, never sideways.

✗ Old Model
One library for all platforms. Fast to start. Catastrophic to maintain. Every change ripples unpredictably because there's no separation between shared foundations and platform-specific needs.
✓ New Model
Foundation + Platform layers. A shared core defines what's universal — platform libraries extend without redefining the foundation. Changes flow down, never sideways.

The architecture

Level 1Global Foundation
Raytail Style Guidelines. Primitives, Typography, Brand, Base Logic. Published once. Consumed by all three platform libraries.
Level 2Platform Libraries
POS gets 48px touch targets and dark surfaces. Web gets light surfaces and dense tables. Mobile gets gesture-aware components and bottom sheets. Each extends the foundation — none redefine it.

Why not just adopt Carbon or Material?

Option A Consume IBM Carbon as the foundation

Skip the foundation layer entirely. Inherit a battle-tested system. Rejected: Raytail's POS hardware needed 48px+ touch targets and high-contrast retail-lighting tokens Carbon doesn't expose. Theming Carbon back to brand spec would have been a constant fight against its defaults.

Option B Single shared library across all platforms

One Figma file. One token set. Rejected: Same model as the old system — the one we were replacing because every change rippled unpredictably. Speed today, drift tomorrow.

Option C · picked ✓ Two-level federation

Foundation owns primitives; platform libraries own composition. Slower to set up, but the only model where a platform team can add a POS-specific dark-mode token without breaking Mobile.

04 — Token Architecture

Three tiers. Zero ambiguity.

The token system needed to be strict enough to prevent drift, but flexible enough to support three different surfaces. I designed a three-tier model — reviewed weekly with the platform engineer.

  • ·Tier 1 — ReferenceRaw primitives. color/green/500: #1B7A4A. Never used in components directly. These are the atomic building blocks that only semantic tokens reference.
  • ·Tier 2 — SemanticNamed by intent. action/primary resolves differently per platform. surface/base is #0D0E0F on POS, #FFFFFF on Web. Same name, appropriate value.
  • ·Tier 3 — ComponentScoped overrides. button/bg/primary points to action/primary. Reskin without touching globals. The escape hatch that never breaks the system.
// Tier 1 — Reference color/green/500: #1B7A4A // Tier 2 — Semantic (per platform) action/primary → color/green/500 surface/base [POS] → #0D0E0F surface/base [Web] → #FFFFFF // Tier 3 — Component button/bg/primary → action/primary

The three-tier model meant a brand color change was now a single token update at Tier 1. It propagated through semantic and component tokens automatically. No manual hunt. No missed screens.

06 — Components

Atoms, molecules, organisms.

The component strategy followed the same two-level split as the architecture: global atoms owned by the foundation, platform molecules and organisms owned by each team.

  • ·Atoms (Global)Color, Type Scale, Icon Set, Spacing, Radius, Shadow. Defined once. Inherited everywhere. No platform can redefine these.
  • ·Molecules (Platform)POS: Numpad, Transaction Row. Web: Data Table, Filter Chip. Mobile: List Item, Bottom Sheet. Each platform builds what it needs from shared atoms.
  • ·Organisms (Platform)POS: Transaction Panel, Product Grid. Web: Analytics Header, Inventory Table. Complex compositions that only make sense in their platform context.
The system was built. Now it needed rules to stay alive.
07 — Governance

Rules that prevent drift.

A design system without governance is a wiki that nobody reads. I established four rules — each one addressing a specific failure mode from the old model.

  • ·Foundation Team owns Level 1Breaking changes require cross-team coordination. No silent updates.
  • ·Platform Teams own Level 2Can add components freely. Cannot redefine global tokens. Gaps become proposals, not workarounds.
  • ·Naming Conventioncategory/property/variant. Enforced globally. Inconsistent naming is the #1 cause of drift.
  • ·Docs live in FigmaDocumentation that drifts from the component is worse than no documentation. If the doc isn't attached to the component, it doesn't exist.

The critical rule: global token updates sync all platforms on publish. Manual propagation is architecturally impossible. The system enforces consistency — it doesn't rely on discipline.

10 — Reflection

What I would revisit.

Two things I'd take into v2 of the system, knowing what I know now.

Lesson 01Motion Tokens

Left out of v1. Platform teams implemented animations independently — creating jarring inconsistencies that only surfaced at QA. Motion should have been a foundation-level concern from the start.

Lesson 02Theming Architecture

The two-level model supports white-labeling — but only if semantic tokens never reference raw hex directly. This constraint needs to be enforced architecturally, not documented.

Time Machine

If I could go back.

The thing I'd change earliest: ship motion tokens alongside color and spacing on day one.

What I assumed
Motion tokens from day one
Include animation and motion tokens in the initial system release.
