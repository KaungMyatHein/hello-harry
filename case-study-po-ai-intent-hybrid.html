01 — The Problem

"Show me past 2 weeks." The dashboard couldn't.

A Myanmar live-seller has one question every Sunday: what did I sell in the past 2 weeks? One sentence. Clear intent.

The CRM dashboard turned that one sentence into a five-step hunt — and most sellers gave up halfway through.

01OpenOrders tab, buried two levels deep behind a menu they didn't read.
02FilterNo "past 2 weeks" preset. Pick a start date and an end date by hand.
03TranslateEvery label in English. Sellers think in Myanmar.
04Scroll600 rows, no summary at the top. Lose your place. Start again.
05Give upRebuild the answer in Excel by hand. Sunday gone.
The seller already knew the question. The system made them prove it.

03 — The Classifier

LLM as classifier. Tools as verbs.

First pass was 30+ regex families. It worked — until a seller said "ဒီတစ်ပါတ် ဘယ်လောက်ရလဲ ပြပြီး ပြန်မှာရမယ့်ဟာတွေပါ ပြပေး" in one sentence. Two intents, conjoined, with paraphrase. Regex caught one and missed the other.

So the architecture flipped. Gemini 2.5 Flash does the classification. The app exposes a fixed vocabulary of 16 tools — each one a single verb the AI is allowed to perform. No tool call, no action. The LLM never touches the database directly.

InputFree-form query"ဒီလ ရောင်းအား တက်လား · ဘာတွေ ပြန်မှာရမလဲ"
→
ClassifierGemini picks 1–6 toolsLLM as classifier. Tool schemas are the vocabulary, scoped to businessId.
→
RenderInline card, not chatServer runs the tools. The page renders results in-place — not as a chat bubble.

Three hops per turn

Hop 1 · LLM picks tools
get_revenue_trend(30) + get_smart_reorder()
Hop 2 · server runs them
Real Prisma queries · scoped to businessId from the JWT
Hop 3 · LLM composes reply
Bilingual answer · cites real numbers · renders inline card

Up to 6 hops per turn. One question can read three things, decide, and stop — all before the user sees anything. The properties this gives me:

  • ·GeneralityAny phrasing in MM, EN, or mixed. No rule to write per variant.
  • ·Composition"Show this AND do that" is one turn, not two.
  • ·SafetyWrite tools live behind a confirm-intent rule baked into the system prompt.
  • ·AuditabilityEvery turn logs tool_name(args) → result. The reply can be replayed.
Inside a Tool

A tool is a verb the AI is allowed to say.

Each tool is a JSON schema (so the LLM knows when to pick it) + a server handler (the only code that touches the DB). The schema's description is the prompt — bilingual phrases the seller might use go directly into it.

That description doubles as the discovery layer: when a seller types "ပြန်မှာရမယ့်ဟာ ဘာရှိလဲ", the LLM matches that phrase against the description text and picks the right verb. The orchestration loop is intentionally simple — the LLM calls a tool, the server runs it, the result goes back, repeat up to 6 hops. No state. All intelligence lives in the schema descriptions.

Bilingual Matching

Myanmar isn't English in different glyphs.

Myanmar glues grammar particles onto the noun — possession, subject, plural. No spaces. No apostrophes. No cues for a Latin-tuned classifier.

The model handles this for free; the design work is loading each tool's description with the bilingual phrasing sellers actually use.

  • ·System prompt sets language stanceReply in Myanmar by default; switch to English only when the user does.

Reflection

Stop teaching users your menu.

Six things I'd take into the next AI surface. The most important: schema descriptions are the new IA.

Lesson 01A command palette is a contract

It's not a UI pattern. The seller speaks naturally; the system promises to meet them there. Break that contract once and you lose trust on every later intent.

Lesson 02Schemas are IA

Tool descriptions are how users navigate now. Write them like nav labels, not API docs. The bilingual phrases live in the description — the LLM does the matching.

Lesson 03Don't pretend Myanmar is "English with different glyphs"

Postpositions, subject markers, and stacked digits need first-class support — not retrofits. Bilingual is one field, not a language toggle.

Lesson 04Composition over duplication

One list_orders verb powers four intents. Don't ship a new tool when arguments already cover it. Ranking ≠ enumeration.

Lesson 05Regex is a feature, not a fallback

Predictable behaviour is itself a way of reducing what the user has to learn. The LLM is the rare path, not the default — when latency matters, regex wins.

Lesson 06Scope the scope

Every tool runs scoped to businessId. Security model is the only thing you can't add later. The LLM picks which verb. The server decides what's allowed.
