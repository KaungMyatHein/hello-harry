02Agent + Grill — where the leverage compounds

The speedup isn't from agents alone. It isn't from grilling alone either. It's from the combination — specialised agents that do the work, plus a grilling discipline that calibrates the work to your specific users, data model, and product conventions.

The agents that did the work

Agent Harry is a 15-subagent pipeline running inside Claude Code. For SF-35, five agents carried the load:

  • orchestrator — parsed the kickoff command, fetched SF-35 from the Notion Sub-Features database, queued the downstream agents in dependency order, and held each one until its predecessor's grill round finished.
  • lo-fi-designer — produced a 304-line markdown handoff with three ASCII layout alternatives (Primary / Alternative / Risky), a Mermaid userflow, a design-system inventory, and 5 open questions. Never drew only one layout — the agent's own anti-patterns list forbids it.
  • design-engineer — three iterations producing real Next.js + React code. 10 prototype files, a mock backend with realistic 800ms Promise.all delay, all 5 mandatory states wired behind a dev chip + query params. Iteration 3 wired the spotlight into the real production headers.
  • handoff-engineer — read every prior artifact (PRD, lo-fi, prototype source, audit ledger, production code) and composed a decision-grade engineering doc: 4 component contracts with "Don'ts", 7 design tokens flagged locked-or-swappable, 6 telemetry events with full payload schemas, a 10-step a11y test script.
  • grill-me — the calibration layer wrapped around all four. Ran four rounds total: lock the spec, polish the lo-fi, find code bugs, scope the handoff.

Each agent has its own anti-patterns list. Each one writes its work product as a versioned local artifact, so the next agent in the chain reads real input, not a verbal handoff. That's what makes the pipeline composable instead of brittle.

What grilling adds on top

The agents would still ship something competent without grilling. With grilling, they ship something calibrated. Four rounds, four different leverage points:

  • Round 1 (lock the spec, 7 min). Twelve load-bearing decisions before a pixel is drawn: corpus scope, match fields, ranking tiers, latency budget, cross-branch fallback. The grill flagged that phone matching would table-scan without a new DB index — captured as a backend prerequisite SF before the prototype even started.
  • Round 2 (polish the lo-fi, 30 min). Thirteen deltas the lo-fi-designer missed: a missing loading state, an action-bar layout shift, a dead-end no-results state, three discoverability layers. Each folded back into the locked spec.
  • Round 3 (grill the code, 12 min). Five real bugs that pure spec-grilling could not have caught:
    1. Fake database relationship — patients don't carry a direct branch reference; scope is inferred through appointments. Engineering would have rewritten it.
    2. useEffect race — forced "Loading" state would flash for <1s before debounced search overwrote it.
    3. "Open Daw" doesn't mean what you think. For Burmese patients with honorifics (Daw Khin Mar Lay, U Tin Aung), the first word IS the honorific. Fix: a tiny dictionary stripping Daw / U / Ma / Ko / Maung / Mr / Mrs / Dr.
    4. Unspecified affordance — design-engineer slipped in a "Reset to {branchLabel}" link. Kept it, but documented it as an addition with a kill switch.
    5. Mobile sheet wasn't built — deferred per Round 1, captured as a backlog SF with TODO(SF-35), not pretended-shipped.
  • Round 4 (scope the handoff, 7 min). Seven decisions about what the handoff doc must contain versus what stays open. Telemetry expanded from the PRD's 1 event to 6 events with full payloads. Each component got a "when NOT to use this" section.
"Agents ship the work. Grilling makes sure the work is calibrated to your users, not a generic best-practice average."

That's the formula. Specialised agents × four rounds of grilling = 1h 53m end-to-end, with the cultural detail (Burmese honorifics), the technical prerequisite (DB index), and the contracted surfaces (4 components, 6 events, 10-step a11y script) all caught before engineering sees the code.

03What got shipped

Five mandatory states — all reachable via query params, all runtime-verified at HTTP 200. Captured by Playwright inside the real product chrome, not a fabricated shell.

04Figma Make vs Agentic — side by side

The asymmetry isn't from any one step being magic. It's that the agentic designer's work product is the working thing — code committed. The Figma designer's work product is a spec for the working thing — frames + manual prototype + redlines.

Where Figma Make still wins

The case isn't that Figma is obsolete — it's that Figma is no longer the mandatory tool for shipping a working interaction.

  • Visual exploration before constraints are set. When you don't know what the product is yet, Figma Make diverges faster than ASCII layouts.
  • Design-system maintenance. Figma variables + Code Connect remain the cleanest way to keep a DS synced across design and code.
  • Stakeholder reviews and marketing mockups. When the deliverable is "show this to leadership", pixel-perfect frames are still the right artifact.

For everything else — taking a PRD with a clear problem and shipping a working, instrumented, handoff-ready interaction — Figma is no longer the necessary tool.

What I'd carry forward

  1. Specialised agents × grilling — that's the formula. Agents are what made 1h 53m possible; grilling is what made the output calibrated to this product instead of a generic best-practice average. Either one alone would have shipped something forgettable.
  2. Grill the code, not just the spec. Round 3 caught a fake database field, a useEffect race, a Burmese honorific bug, an unspecified affordance, and a mobile gap — none of which spec-grilling could have surfaced.
  3. The handoff is the artifact. The prototype is theatre. The component contracts with explicit "Don'ts", the telemetry payload schemas, the a11y test script — that's what engineering reads.
  4. Production-code modifications need explicit gates. The pipeline rightly flagged the "wire into real product" step as an anti-pattern and required an explicit override. Treating that as a real gate is the safety an agent without governance would skip.
