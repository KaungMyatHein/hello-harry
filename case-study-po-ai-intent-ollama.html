##01 · the problem

In 21 contextual interviews, every SMB seller had the same friction: app-switching while their hands were full. Messenger chats, the seller app, a paper notebook. They wanted to say it once and have the system file the order, deduct stock, print a receipt, tag the buyer.

// observed in interviews
while (selling) {
  hold(product);
  glance(camera);
  switchApp("messenger");
  typeOrder(); // blocked — only one free hand
  switchApp("sellerApp");
  deductStock();
  scribbleOnPaper(); // for the receipt later
}

##03 · intent mapping

No LLM gets to invent verbs. The model selects from a closed set of 28 named tools. Each tool has a JSON schema. The model fills slots; the runtime validates and executes. If a slot is missing, the assistant asks one targeted question.

##05 · bilingual by default

Real sellers mix languages every sentence. We trained the router on 4,200 code-switched utterances. Zero translation step. The router operates on tokens, not language tags.

# pure burmese
> "ဆေး နှစ်ဖူး ထည့်ပေး၊ ဈေး နှစ်ထောင်"
  → order.create(item=ဆေး, qty=2, price=2000)

# pure english
> "add two units, price two thousand"
  → order.create(item=<ambiguous, prompt>, qty=2, price=2000)

# code-switched
> "stock ၃ ဖူး deduct, receipt print ပေး"
  → stock.deduct(qty=3) → receipt.print(ref=last_order)

##∞ · reflection

01.
Tools, not freeform text.
Closing the action set to 28 tools killed an entire class of hallucination error.
02.
Latency is the feature.
Below 50ms feels like causation. Above 200ms feels like a server. Optimize phase-by-phase.
03.
Bilingual is one language.
Treating code-switching as a first-class input — not a translation step — cut router complexity in half.
04.
The card is the truth.
Voice in, card out. The seller never re-listens. They glance, tap, move on.
