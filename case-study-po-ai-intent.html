Sellers stopped clicking. They started speaking.

A Myanmar live-seller's day is one long stream of "show me X, then do Y." The CRM dashboard turned every question into a five-step hunt. I replaced the navigation model with a bilingual intent palette wired to Gemini tool-calling — type or speak, the LLM picks the right verb, the answer renders inline.

01 — The Problem

"Show me past 2 weeks." The Dashboard Couldn't.

A Myanmar live-seller has one question every Sunday: what did I sell in the past 2 weeks? One sentence. Clear intent.

The CRM dashboard turned that one sentence into a five-step hunt — and most sellers gave up halfway.

  • Open — Orders tab, buried two levels deep
  • Filter — no "past 2 weeks" preset; pick start & end dates manually
  • Translate — every label in English, sellers think in Myanmar
  • Scroll — 600 rows, no summary at the top
  • Give up — rebuild the answer in Excel by hand
The seller already knew the question. The system made them prove it.

Three Axes

Tag Every Intent. Three Times.

Each intent is classified along three axes. Together they decide the card type, the confirm gate, and whether it can chain. Chainable says whether the result can feed a follow-up. Confirm says whether to gate the action behind a destructive button. Response says whether to render a UI card or a text reply.

Chainable × Confirm × Response = the rendering rule.

Intent Taxonomy

Verb × Noun.

A conversation grammar. Combine a verb with a noun (+ modifiers) to form an intent. The verb decides the rules — render, confirm, chain. Six verb classes (Read, Create, Modify, Delete, Action, AI) crossed with six noun classes (Commerce, Sales, Customer, Marketing, Insights, Config) cover every intent without bespoke parsing.

03 — The Classifier

LLM as Classifier. Tools as Verbs.

First pass was 30+ regex families. It worked — until a seller said "ဒီတစ်ပါတ် ဘယ်လောက်ရလဲ ပြပြီး ပြန်မှာရမယ့်ဟာတွေပါ ပြပေး" in one sentence. Two intents, conjoined, with paraphrase. Regex caught one and missed the other.

So the architecture flipped. Gemini 2.5 Flash does the classification. The app exposes a fixed vocabulary of 16 tools — each one a single verb the AI is allowed to perform. No tool call, no action. The LLM never touches the database directly.

Input
Free-form query
"ဒီလ ရောင်းအား တက်လား · ဘာတွေ ပြန်မှာရမလဲ"
→
Hop 1 · LLM picks tools
get_revenue_trend(30) + get_smart_reorder()
Hop 2 · server runs them
Real Prisma queries · scoped to businessId
Hop 3 · LLM composes reply
Bilingual answer · cites real numbers · renders inline card

Up to 6 hops per turn. One question can read three things, decide, and stop — all before the user sees anything.

  • Generality — any phrasing in MM, EN, or mixed. No rule to write per variant.
  • Composition — "show this AND do that" is one turn, not two.
  • Safety — write tools (create, update, delete) live behind a confirm-intent rule baked into the system prompt.
  • Auditability — every turn logs tool_name(args) → result. The reply can be replayed.
03b — Inside a Tool

A Tool Is a Verb the AI Is Allowed to Say.

Each tool is a JSON schema (so the LLM knows when to pick it) + a server handler (the only code that touches the DB). The schema's description is the prompt — bilingual phrases the seller might use go directly into it.

// Declaration — the LLM reads this { name: 'get_smart_reorder', description: 'AI-derived reorder suggestions: per variant, returns velocity (units/day past 30 days), days_left, and suggested reorder qty. Use for "smart reorder", "ဘာတွေ ပြန်မှာရမလဲ", "ပြန်ဖြည့်ဖို့", "stock ကုန်ခါနီးတာ ဘာရှိလဲ".', parameters: { type: 'OBJECT', properties: {} }, } // Handler — the server runs this · scoped to businessId async function handleSmartReorder(args, ctx) { const sales = await ctx.prisma.orderItem.groupBy({ where: { order: { businessId: ctx.businessId, ...last30Days } }, _sum: { quantity: true }, by: ['variantId'], }); return sales.map(velocityToReorder); }

Three rules every tool follows:

  • Scoped — every query carries businessId from the JWT. The AI cannot widen the blast radius.
  • Bilingual in the description — MM + EN trigger phrases live in the schema, not in the prompt. Tools self-document.
  • Confirm before write — system prompt forces a one-line confirm reply for any create/update/delete unless the user already gave full details.
The LLM picks which verb. The server decides what's allowed. Two layers, never confused.
04 — Bilingual Matching

Myanmar Isn't English in Different Glyphs.

Myanmar glues grammar particles onto the noun — possession, subject, plural. No spaces. No apostrophes. No cues for a Latin-tuned classifier. The model handles this for free; the design work is loading each tool's description with the bilingual phrasing sellers actually use.

English
"show me pending orders"
↓ matches
list-orders · status=PENDING
Myanmar
"လက်ကျန်အော်ဒါတွေပြပါ"
↓ matches
list-orders · status=PENDING
Mixed
"pending order ပြပါ"
↓ matches
list-orders · status=PENDING
  • Trigger phrases in the schema — every tool's description includes the MM, EN, and mixed forms a seller might ask. The model picks the right verb without prompt-engineering tricks.
  • Server-side normalisation — Myanmar digits (U+1040–U+1049) → ASCII before any DB query. The LLM doesn't have to know.
  • System prompt sets language stance — reply in Myanmar by default; switch to English only when the user does. Keeps voice consistent across all 16 tools.

Cards, Not Chat Bubbles.

Ask "low stock" → get the actual list, sortable, with adjust-stock CTAs per row.

06 — Inventory Read Flow

Browse the Shelf, Spot What's Low.

Inventory mirrors a physical shop — the seller already understands it. So I shipped the palette here first: same data, new front door. The five reads that anchor every later workflow — list, detail, low-stock, adjust, history — proved the card pattern on familiar ground before I asked the seller to trust it for orders or money.

list-products product-detail low-stock adjust-stock stock-history
  • Read first, then write — the five reads that anchor every later workflow
  • Same data shapes — every later phase aggregates products, orders, and customers from this base
  • Lowest-risk start — the seller's mental model of inventory survives; only the entry point changes
list-products
07 — Order Lifecycle Flow

From Pending to Paid, Without Leaving the Palette.

The seller's busiest loop: see what's pending, open one, verify the payment slip, mark it paid — sometimes cancel, sometimes export at end-of-day. In the old app each step was three to four clicks across two pages. Collapsing the most-repeated workflow first produced the most felt relief per intent shipped.

list-orders order-detail create-order update-order-status verify-payment cancel-order export-orders
  • Header — icon pill + label + headline number
  • Filter row — sticky chips with counts
  • Body — top 8 rows + "N more" footer
  • Footer — one CTA. Never two.
list-orders
08 — Customer Insight Flow

Know the Buyer Before You Reply.

Sellers don't just ship orders — they remember regulars. Who bought what, who's behind on payment, who deserves a private discount. Four intents that turn a name into context, without leaving the palette open on the message thread.

list-customers customer-detail search-customers customer-stats
  • Search by name in either language — Myanmar possessives strip cleanly to a bare name
  • Detail card — total spend, last order, recency badge, jump to that customer's order list
  • Stats card — top customers by revenue, ranked with gold/silver/bronze pills
customer-stats
09 — Product Write Flow

Edit the Catalog Without Leaving the Question.

Once the read flow earned the seller's trust, write actions could ride on the same surface. Create, edit, delete — and bulk-edit stock for the every-Saturday restock. Destructive flows use a two-step pattern: preview state, then confirm state. No window.confirm. No modal stacking on top of the palette.

create-product update-product delete-product bulk-update-stock
  • Bulk Update Stock — inline spreadsheet in 320px of vertical space
  • Dirty-row tracking — "Save N changes" CTA disables when nothing is dirty
  • +10 / +50 quick fills — restock the common case without typing
  • Two-state delete — preview consequences, then a destructive confirm button
bulk-update-stock

Reflection

What I Learned

01 — A command palette isn't a UI pattern. It's a contract.

The seller speaks naturally; the system promises to meet them there.

02 — Don't pretend Myanmar is "English with different glyphs."

Postpositions, subject markers, and stacked digits need first-class support — not retrofits.

03 — Matching intent is half the problem.

Matching the user's expectation of the result is the other half. Ranking ≠ enumeration.

04 — Regex is a feature, not a fallback.

Predictable behaviour is itself a way of reducing what the user has to learn. The LLM is the rare path.
