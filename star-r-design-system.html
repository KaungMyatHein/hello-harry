01 · Situation
The pain

47 duplicate tokens. 3-day onboarding.

Raytail's design assets lived in 3 separate Figma files for POS, Web, and Mobile — with 47 duplicate tokens, conflicting naming, and a designer onboarding ritual that took 3 full days just to learn which colour to use where.

02 · Task
The deliverable

One source. Three expressions.

Build a single design system architecture serving POS, Web, and Mobile from one source of truth, so token decisions stopped being re-negotiated per-platform.

03 · Action
What I did

Primitive → semantic → component.

  • Designed a 3-tier token architecture — primitive, semantic, component — that mapped cleanly across all three platforms.
  • Audited every existing token across the 3 Figma files and consolidated the 47 duplicates into the primitive layer.
  • Built the semantic layer in Figma Variables so each platform consumed the same source but expressed it natively (POS density different from Mobile).
  • Walked the architecture through each platform team — IS, Development, CS, Warehouse, Finance — to sell migration rather than impose it.
  • Partnered with engineering on a token-name lint rule so the architecture was enforced in code review, not just docs.
03a · Technical
How it works under the hood

Three tiers. One contract per platform.

Tier 01 · Primitive
Raw values — hex codes, scale steps, motion durations. Never used directly in component code; consumed by Tier 02 only.
~80 primitives
Tier 02 · Semantic
Intent-named bindings — color.surface.muted → primitive. Bound per platform via Figma Variables (POS density ≠ Mobile density).
~140 semantics
Tier 03 · Component
Component-scoped tokens — button.primary.bg → semantic. Live closest to the UI, replaceable per surface without touching primitives.
~60 component tokens
Lint Rule eslint-token-name.js 
// Enforces 3-tier naming · blocks at code review
const tokenPattern = /^(color|space|font|motion)\.
  (surface|content|border|action)\.
  (default|hover|active|disabled|muted)$/;

module.exports = {
  create: ctx => ({
    Literal: node => {
      if (!tokenPattern.test(node.value))
        ctx.report(node, "Token must match 3-tier schema");
    }
  })
};
// → 100% violations caught pre-merge

05 · Reflection
What I'd do differently

Migration story over token tree elegance.

I built the architecture first and the migration playbook second — but the playbook was what actually drove adoption, so it should have been a v1 deliverable, not v2. Lesson — design systems live or die by their migration story, not by the elegance of their token tree.
