# Case Study Writing Guide

## Story Arc Structure

Every case study follows this narrative arc in order:

1. **Hook/Hero** — Bold statement or question (4-8 words). e.g. "Meet the world's smartest crib"
2. **Context** — Company, product, and role. Set the scene in 1-2 sentences.
3. **Problem** — Define the challenge clearly. One strong statement.
4. **Research/Discovery** — Show the process: interviews, audits, ethnographic research.
5. **Solution/Design** — Walk through design decisions with wireframes, iterations, prototypes.
6. **Impact/Results** — Quantify outcomes with bold, isolated metrics.
7. **Reflection** — Lessons learned and personal growth insights.

## Section Numbering

Use two-digit numbered phases for clear progression:
- Format: `(01) Section Name` with a one-line descriptor underneath
- e.g. `(01) Challenge` → `(02) Immersion` → `(03) User Research` → `(04) Design` → `(05) Impact`

## Headlines

- **Main headline:** 3-6 words, evocative, not descriptive. e.g. "Designing for Scale", "Connecting Humans", "Social Commerce"
- **Subheadline:** One sentence, human-centered, outcome-focused. e.g. "Removing obstacles for parents with accurate data and stunning UX"
- **Question headlines** for engagement: "What's the problem we're trying to solve here?"

## Typography Hierarchy

- **Section number:** Small, muted, monospace or sans-serif (`01`, `02`)
- **Headline:** Large, bold, serif or display font
- **Subheadline:** Medium, lighter weight
- **Body:** Regular weight, comfortable reading size

## Body Text

- Write in **first person** ("I was tasked with...", "We scheduled...")
- **Conversational but professional** tone — not formal, not casual
- Present tense for process, past tense for actions
- **Empathy-forward** — center the user's problems, not the designer's ego
- Short opening sentences that hook
- Mix short and medium sentences — max ~25 words per sentence
- Concrete over abstract: specific numbers, user quotes, methods
- **2-3 sentences per paragraph max** — single-sentence paragraphs for emphasis
- No dense walls of text

## Visual Text Elements

### Metadata (always display prominently)
- Role: "Lead Designer", "Senior Designer"
- Company/Client
- Timeline/Date
- Team credits with names and roles
- Platform: "iOS Mobile", "Android", "Web"

### Impact Metrics
- Pull numbers OUT of paragraphs into standalone visual elements
- Large font, accent color, supporting label underneath
- e.g. "7x increase", "80% of traders", "5 traders interviewed"

### Frameworks & Lists
- RICE scoring, JTBD, competitive analysis categories
- Must-haves vs. Top contenders
- Bullet lists for research findings

## Storytelling Techniques

1. **User Quote Opening** — Start with a real quote to ground the story in human need
2. **Tension & Resolution** — Present a problem stat, then reveal the solution
3. **Behind the Curtain** — Share actual process details ("I joined WhatsApp groups to be a fly on the wall")
4. **Philosophy Statements** — Bold, quotable lines that reveal design values ("Design innovates within constraints")
5. **Acknowledging Constraints** — Don't hide limitations, it builds credibility

## Text Style Cheat Sheet

| Element | Pattern | Example |
|---------|---------|---------|
| Hero Title | 4-8 words, evocative | "Meet the world's smartest crib" |
| Section Number | Two-digit, muted | "01", "02" |
| Section Headline | 2-4 words, bold | "Designing for Scale" |
| Subheadline | One sentence, outcome | "Removing obstacles for parents" |
| Body | 2-3 sentences, first person | Short, concrete |
| User Quote | Italic, attributed | "It'd be easier to run with a group" |
| Metric | Large, isolated | "7x increase" |
| Metadata | Label: Value | "Role: Lead Designer" |
| CTA | Warm, inviting | "Let's work together" |

## Key Rules

1. Lead with the human problem, not the product feature
2. Keep headlines under 6 words — subheadlines explain
3. Pull metrics out as standalone visual elements
4. Include at least one direct user quote
5. Show constraints, not just solutions
6. End with reflection, not just results
7. Credit team members by name and role
8. Never more than 3 sentences per paragraph
